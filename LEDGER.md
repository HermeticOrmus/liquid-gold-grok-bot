# Ledger: the library

Cracks in the tools and platform facts every entry depends on: the gbot CLI, the template format, the checks. Each bot's own cracks are in its folder's LEDGER.md. IDs are never reused.

| ID | Crack | Evidence | Grade | Tracker | Seal | State |
|----|-------|----------|-------|---------|------|-------|
| K-01 | `gbot bots create --help` (grok-bot-cli 0.2.3) sends a create request instead of printing help. With a `--name` on the line it would create a bot. | grok-bot-cli 0.2.3 `src/cli.js:224` treats `--help` only as the first argument; `src/cli.js:280-282` calls `createAgent` for any `bots create` arguments. Our run printed `createAgent failed: 400 createAgent: args.name: must be string, got undefined`; a read-only `gbot bots list` showed nothing was created. | fracture | Fixed upstream: grok-bot-cli 0.11.2 answers `--help` per command | `scripts/create-bot.sh` and `scripts/create-team.sh` print by default, run only with `--yes`, and never pass `--help` to gbot. The README says to update gbot. Small. | sealed #2 |
| K-02 | The `--instructions` flag is gone from `gbot bots create` in grok-bot-cli 0.11.2, and in 0.2.3 `--description` and `--instructions` are one key where the last one wins. | 0.11.2 `bots create` options: name, description, title, avatar-shape, avatar-color; its README: "`--description` is the UI Instructions field". 0.2.3 `src/cli.js:118` (`takeLastFlag(args, "--description", "--instructions")`). | hairline | new | The scripts pass instructions.md as `--description`, which both versions read as the Instructions field. Small. | sealed #2 |
| K-03 | gbot 0.2.3 rejects a flag value that starts with a dash, so instructions that open with a list item cannot be passed. | grok-bot-cli 0.2.3 `src/cli.js:65`: `if (value == null \|\| value.startsWith("-")) throw ... "needs a value"` | hairline | new | `scripts/check.py` fails any instructions.md that does not open with a letter. Small. | sealed #2 |
| K-04 | The sharing button has two names: the [Templates guide](https://x.ai/bot/guides/templates-for-grok-bot) says "Share as Template" in settings; the [docs](https://docs.x.ai/grok-bot/bots#share-a-bot) say the Share menu, Create template. | Both pages, read on 2026-09-30. | hairline | new | Every template.md names both. Small. | sealed #2 |
| K-05 | Whatever a bot's shared text holds is public: a public link shows the bot's configuration, and marketplace listing pages show memory text. | [Docs](https://docs.x.ai/grok-bot/bots#share-a-bot): a public link "shows the Bot's shared configuration, including its identity, description, skills, and routines". The [Engineer Bot listing](https://x.ai/bot/marketplace/bots/engineer-bot) shows its memories as page text. | break | new | `scripts/check.py` scans every file for the private leak list and generic patterns, and keeps template text (instructions, skills, routines, laws) free of the publisher's name. CI runs it on every PR. [RUBRIC.md](RUBRIC.md) stage 5. Medium. | sealed #2 |
| K-06 | Separate bots are not a security boundary: all bots on an account share one computer, its files, browser sessions and logins. | [FAQ](https://docs.x.ai/grok-bot/faq): "They share its files, browser sessions, and logins"; "Do not use separate Bots as a security boundary." | fracture | new | Every plugins.md lists Ask first rules as the boundary; both team laws say to work only in the project's own checkout folder. Small. | sealed #2 |
| K-07 | A forbidden-words list in a public CI file would publish the client, project and host names it exists to hide, and a hashed list is no better: anyone can hash a guessed name and confirm it. | Found while writing `scripts/check.py` for this PR; the first seal (salted hashes) was itself cracked in review, because a public salt turns the list into a guess checker. | break | new | The list never enters the repo in any form. CI runs only generic patterns (paths, addresses, chat ids, phone numbers, network names, tokens, em dashes); the maintainer runs the private check locally before merging with `LEAK_LIST=<file outside the repo> python3 scripts/check.py`, where plain terms match as whole words and regex lines as written. Proven by planting every private term in a scratch file: each one fails the check. Small. | sealed #2 |
| K-08 | xAI documents what a skill should state but no file format for skills inside a template. | [Skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations) lists six things a useful skill states and names no file format; the [Templates guide](https://x.ai/bot/guides/templates-for-grok-bot) says templates include skills without a format. | hairline | new | Skills here use the Agent Skills format (`SKILL.md` with `name` and `description` frontmatter) with the six parts as sections; every README with a skill says so. grok-bot-cli 0.11.2's README says `gbot skills add` posts a `SKILL.md` to the account's one skill library. Small. | sealed #2 |
| K-09 | A routine spends usage every time it runs, even when it has nothing to say. | [Skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations): broad listeners "create noise, consume usage". | hairline | new | Every routines.md fills the six fields the docs name and carries a Cost line; RUBRIC stage 2. Small. | sealed #2 |
